# PRD — R1 (올리고 · 열고 · 찾는 기본 순환)

> 단계: 명세 / 상태: 구현·시험 완료 (R1-1~5, 아래 "구현 결과" 참고) / 작성일: 2026-11-25
>
> 범위는 `03-우선순위.md` 의 R1 이다. 규칙의 근거는 `02-정책서.md`(A1~S3), 구조 결정은 `04-인프라.md` 다. 각 항목에 **정함**(사용자가 결정)과 **가정**(내가 임시로 둠)을 표시했다. 로그인과 직원 명단은 이미 구현돼 있어 이 문서의 범위가 아니다.

## 목표와 성공 기준

- 목표: 로컬 HTML 을 올려 링크 한 줄로 공유하고, 나중에 목록·검색으로 다시 찾는다 (J1·J3·J4).
- 북극성 지표: 주간 열람된 문서 수 (가정, 기획 단계 후보). R1 이 나가면 이 값을 재기 시작한다.
- R1 에 없는 것: 새 버전 교체·이력·되돌리기, Claude 명령 업로드(R2), 본문 검색·댓글(R3).

## 사용자 스토리와 인수 조건

각 조건은 "참이면 통과"로 읽는다.

### R1-1 웹으로 올리기 (U1~U5, 가정)

올리는 직원으로서, `.html` 파일 하나와 제목·프로젝트를 입력해 올리고 링크를 받는다.

- 로그인한 직원만 올리기 화면을 본다. 로그아웃 상태면 로그인으로 보낸다.
- 제목은 필수다. 비어 있으면 올려지지 않고 이유가 보인다.
- 프로젝트는 입력(자유 입력 또는 기존 값 선택)이다. 기존 목록을 어떻게 보여줄지는 설계에서 정한다.
- `.html` 이 아니거나 10MB 를 넘으면 올려지지 않고 이유가 보인다 (U3·U4).
- 올리기 화면에 "전 직원이 볼 수 있습니다" 문구가 보인다.
- 올리면 추측할 수 없는 번호가 붙은 링크가 나오고, 같은 제목으로 두 번 올리면 문서가 두 개 만들어진다 (U5).
- 파일은 Cloudflare R2 에, 제목·프로젝트·올린 사람·시각은 SQLite 에 저장된다 (I4·I5).

### R1-2 링크로 열기 (A1·A3·S1·S2)

직원으로서, 받은 링크를 눌러 문서를 본다.

- 로그인하지 않았으면 로그인 후 같은 문서로 돌아온다 (가정: 돌아오는 동작은 설계에서 확정).
- 명단에 없는 계정은 문서를 보지 못한다 (A4).
- 문서 응답에 `Content-Security-Policy: sandbox allow-scripts` 헤더가 붙는다.
- 문서 안의 JS 가 앱에 요청을 보내도 로그인 세션으로 처리되지 않는다 (시험 문서로 확인한다 — 아직 시험 전).
- 없는 번호나 삭제된 문서는 "없는 문서" 안내만 보인다 (D3).

### R1-3 목록과 검색 (F1 중 제목·올린 사람, F3)

직원으로서, 올라온 문서를 목록에서 보고 제목이나 올린 사람으로 찾는다.

- 로그인한 직원은 모든 문서 목록을 최신순으로 본다.
- 목록의 각 줄에 제목, 프로젝트, 올린 사람 이름, 올린 시각이 보인다.
- 검색어를 넣으면 제목 또는 올린 사람 이름에 그 글자가 든 문서만 남는다.
- 삭제된 문서는 목록과 검색 결과에 나오지 않는다.
- 문서가 많아질 때의 쪽 나누기 방식은 설계에서 정한다 (가정: R1 에서는 한 번에 보이는 개수 제한만 둔다).

### R1-4 프로젝트별 보기 (U2·C3)

직원으로서, 프로젝트를 골라 그 프로젝트의 문서만 본다.

- 목록에서 프로젝트를 고르면 그 프로젝트 문서만 보인다.
- 프로젝트는 분류일 뿐 열람 범위를 나누지 않는다 (A3).
- 소속(부서)은 올린 사람 표시용 정보이며 R1 에서 화면에 보이는지는 정하지 않았다 (미정).

### R1-5 삭제(숨김) (D1·D3·D4)

올린 사람이나 관리자로서, 문서를 화면에서 지운다.

- 올린 사람과 관리자만 삭제 단추가 보이고 동작한다. 다른 직원이 요청을 직접 보내도 거부된다.
- 삭제는 화면에서만 숨긴다. 파일과 기록은 R2 와 DB 에 남는다.
- 삭제한 문서의 링크는 "없는 문서" 안내가 보인다.
- 숨긴 문서를 다시 살리는 화면은 R1 에 없다 (D4-1 의 복구는 관리자가 DB 에서 직접 한다 — 가정). → 2026-11-26 관리자용 `/admin/hidden`(숨긴 문서 목록 + 살리기)을 추가했다. 아래 "관리자: 숨긴 문서 살리기" 참고.

## 비기능

| 항목 | 기준 | 구분 |
|---|---|---|
| 접근 | 로그인과 명단 확인은 매 요청마다 거친다. 공개 화면은 `/login`, `/healthz`, `/privacy`, `/terms` 뿐이다 | 정함 |
| 크기 | 파일 하나 10MB 이하 | 가정 |
| 보안 | 문서 응답에 격리 헤더, 문서 번호는 추측 불가, 올린 사람 확인은 서버가 한다 | 정함/가정 혼합 |
| 안전한 화면 출력 | 제목·프로젝트·이름은 화면에 넣을 때 이스케이프한다 (이미 `escape` 가 있다) | 가정 |
| 가용성 | 맥미니 한 대. 꺼지면 서비스가 멈춘다 (I6) | 정함 |

## 다음 단계

구현 계획(작업 쪼개기)을 쓰고, R1-1 → R1-2 → R1-3·4 → R1-5 순서로 만든다. 순서의 이유: 올려야 열 수 있고, 열 수 있어야 목록이 의미가 있다. 직원 전체 명단은 기능을 만든 뒤 넣는다 (2026-11-25 사용자 결정).

## 구현 결과 (2026-11-25)

맥미니(`https://survey.eunseong.dev`)에 배포했고, 실제 브라우저에서 `eunseong@greenery.im` 로 로그인해 시험했다.

| 항목 | 결과 |
|---|---|
| R1-1 올리기 | 제목·프로젝트·파일로 올려 링크를 받았다. 제목 없음, 200자 초과 제목, `.txt` 파일, 빈 파일, 10MB 초과(10MB+1바이트와 11MB)는 모두 400 과 안내 문구로 거부됐고 문서는 저장되지 않았다 (실서버에 직접 요청해 확인) |
| R1-2 열기 | 로그인 상태에서 문서가 열렸다. 응답 헤더에 `Content-Security-Policy: sandbox allow-scripts`, `nosniff` 가 있다. 문서 안의 JS 는 실행됐지만 `document.cookie`, `localStorage`, 앱으로의 로그아웃 요청이 모두 막혔고, 문서가 실행된 뒤에도 로그인 세션은 살아 있었다. 없는 번호는 404 |
| R1-3 목록·검색 | 최신순 목록, 올린 사람 이름 검색, 없는 검색어(결과 없음) 확인. 제목 검색은 자동 시험(`cargo test`)으로 확인했다 |
| R1-4 프로젝트별 보기 | 프로젝트 선택으로 걸러지는 것을 확인했다. 입력은 자유 입력 + 기존 값 제안(사용자 결정) |
| R1-5 삭제 | 올린 사람이 삭제하자 목록에서 사라지고 링크가 404 가 됐다. 파일은 디스크에 남아 있다 |

**구현하지 않았거나 시험하지 않은 것**
- 로그인하지 않고 문서 링크(`/d/번호`)를 열면 로그인 뒤 그 문서로 돌아온다 (2026-11-25 실서버 확인). 돌아갈 주소는 `/d/<문서번호>` 꼴만 받고 나머지는 목록으로 보낸다.
- 삭제 권한은 실서버에서 확인했다. 올린 사람이 아닌 직원은 403 과 안내를 받고(문서 열기는 가능), 관리자(`role = admin`, DB 에서 직접 지정)는 남의 문서를 삭제할 수 있다. 시험에 쓴 임시 계정은 시험 뒤 명단에서 지웠다.
- 파일 저장은 우선 맥미니 디스크(`FILES_DIR`, 기본 `data/files`)다. R2 는 키가 준비되면 `put_file`/`read_file` 두 곳만 바꿔 붙인다 (사용자 결정, 2026-11-25).
- 올린 사람 이름은 올릴 때의 값을 저장한다. 나중에 명단의 이름이 바뀌어도 기존 문서의 표시는 바뀌지 않는다.
- 쪽 나누기는 없고 최신 200건만 보인다. (2026-11-26 쪽 나누기 추가, 위 "아직 정하지 않은 것" 참고. 실서버 확인: 2쪽에서 "이전"을 누르면 검색어·프로젝트를 유지한 채 1쪽으로 돌아온다. 문서가 1건뿐이라 "다음" 버튼은 자동 테스트로만 확인했다.)
- 한 달 안에 쓰는 사람이 늘면 SQLite 접속이 둘(명단·문서)이라 동시 쓰기가 충돌할 수 있어 대기 시간(5초)을 두었다. 부하 시험은 하지 않았다.

## R2 일부 구현: 새 버전 교체·이력·되돌리기 (2026-11-25)

정책서 V1~V8 을 따랐다. 별도 PRD 없이 정책서가 인수 조건 역할을 한다.

- `/d/<번호>/replace` 에서 올린 사람과 관리자가 새 파일로 교체한다. 링크는 그대로이고 내용만 바뀐다 (V1·V3). 이전 버전은 이력으로 남는다 (V2).
- `/d/<번호>/history` 에 버전 번호, 올린 사람, 시각이 보인다 (V4). 전 직원이 `/d/<번호>/v/<n>` 로 이전 버전을 열 수 있고 같은 격리 헤더가 붙는다 (V5).
- 되돌리기는 이전 버전의 내용을 새 버전으로 한 번 더 저장한다. 중간 버전은 지우지 않는다 (V8). 올린 사람과 관리자만 한다 (V7).
- 이미 올라온 문서는 서버가 시작할 때 1번 버전으로 채운다. 맥미니에서 기존 문서 3건이 채워진 것을 확인했다.
- 실서버 확인: 올리기 → 교체(2번) → 현재 내용 2, 1번 열기 내용 1, 없는 버전 404, 1번으로 되돌리기(3번 생성, 현재 내용 1), 중간 2번 보존, `.txt` 교체는 400. 자동 테스트 12개 통과.
- 권한: 올린 사람이 아닌 직원은 교체·되돌리기·교체 화면이 모두 403 이고 이력 화면에 해당 단추가 보이지 않으며 문서 내용도 바뀌지 않았다 (실서버, 임시 계정으로 확인 후 명단에서 삭제). 시험하지 않은 것: 이력의 저장 공간 관리(V9).
- 화면에서 제목·프로젝트는 교체로 바뀌지 않는다.

## R3 일부 구현: 본문 검색 (2026-11-25)

정책서 F1~F3, D4-3 을 따랐다.

- 검색창 하나가 제목, 올린 사람, 본문을 함께 찾는다. HTML 태그, 주석, `<script>`·`<style>` 안의 내용은 뺀 보이는 글자만 대상이다 (F2).
- 색인은 현재 버전만 둔다. 교체·되돌리기 때 새 현재 버전으로 바뀌고, 이전 버전의 글자는 찾지 않는다. 숨긴 문서는 나오지 않는다 (F3, D4-3 가정).
- 색인 기능 이전에 올린 문서는 서버가 시작할 때 채운다. 맥미니에서 5건이 채워졌다.
- 실서버 확인: 본문 글자로 찾기 성공, `<script>` 안의 글자는 못 찾음, 없는 말은 결과 없음, 교체 뒤 옛 본문은 못 찾고 새 본문은 찾음, 삭제 뒤 안 나옴. 자동 테스트 14개 통과.
- 한계: 본문을 전부 훑는 방식이라 문서가 수천 건을 넘으면 FTS5 로 바꾸는 것이 좋다 (코드에 `shortcut` 으로 표시). 검색 결과에 본문 일부를 보여 주는 것(F4)은 만들지 않았다. 올린 직원이 의식하지 못한 내용(표 안의 숫자 등)도 본문 검색에 걸린다는 점은 정책서 "전 직원 열람의 부담" 그대로다.

## R3 일부 구현: 댓글 (2026-11-25)

정책서 M1~M5 를 따랐다.

- 실서버 확인: 댓글 작성, `<script>` 가 글자로 이스케이프되는 것, 줄바꿈 유지, 빈 댓글·2001자 댓글은 400, 남의 댓글 삭제는 403(쓴 사람은 본인 것만, 일반 직원 기준), 본인 댓글 삭제 후 화면에서 사라짐, 문서를 숨기면 댓글 화면은 404. 자동 테스트 15개 통과. 시험 계정은 명단에서 지웠고 시험 문서는 숨겼다.
- 관리자가 남의 댓글을 지우는 경로도 실서버에서 확인했다 (임시 관리자 계정, 시험 후 명단에서 삭제).
- 하지 않은 것: 댓글 수정, 알림, 댓글 수를 목록에 보여 주기.

## R2 일부 구현: 토큰으로 올리기 (2026-11-25)

정책서 T1~T5 를 따랐다. 사용자가 "MCP 연결 시엔 개인 토큰 발급으로 둬야 한다"고 정했다.

- `/tokens` 에서 발급·폐기하고 `POST /api/upload` 에 `Authorization: Bearer 토큰` 과 `title`, `project`, `file` 을 보내면 `201 {id, url}` 을 받는다. 올린 문서는 토큰 주인 이름으로 기록된다.
- 실서버 확인: 발급 → curl 로 올리기 201 → 문서에 내 이름으로 기록 → 본문 검색에 걸림. 틀린 토큰 401, 제목 없음 400, `.html` 아님 400, 토큰만으로 목록 화면 접근은 로그인으로 이동(303). 폐기 뒤 같은 토큰은 401. 시험 문서는 숨겼고 토큰은 폐기했다. 자동 테스트 18개 통과.
- 비활성화된 직원의 토큰은 401 이 되는 것을 실서버에서 확인했다 (임시 계정). 없는 것: 관리자가 직원의 토큰을 보거나 강제로 폐기하는 기능, 새 버전 교체·삭제용 토큰 API.
- MCP: `scripts/mcp_upload.py` (표준 라이브러리만 쓰는 stdio MCP 서버, 도구 `upload_html`)를 만들었다. 환경변수 `HTML_HUB_URL`, `HTML_HUB_TOKEN` 으로 `/api/upload` 를 부른다. 실서버 확인: 도구 목록, 올리기(링크 반환), 틀린 토큰은 오류 문구를 결과로 돌려줌. 파이썬 기본 User-Agent 를 Cloudflare 가 403(error 1010)으로 막아서 `html-hub-mcp/0.1` 을 지정했다. Claude Code 에 실제로 등록해 대화 중에 쓰는 것까지는 시험하지 않았다 (등록 명령은 스크립트 머리말에 있다).
- Claude Code 등록 (2026-11-25, 맥미니): 사용자 범위로 등록해 `Connected` 를 확인했다. 스크립트를 stdio 로 직접 불러 올린 문서가 목록에 뜨고 문서 속 JS 가 도는 것도 확인했다. 대화 중 도구로 부르는 것은 아직 시험하지 않았다.

## 북극성 지표 측정 시작: 열람 기록 (2026-11-26)

목표의 "R1 이 나가면 이 값을 재기 시작한다"를 따랐다.

- 현재 버전 링크(`/d/<번호>`)가 열릴 때마다 `views` 테이블에 문서 번호와 시각만 남긴다. 누가 봤는지는 남기지 않는다 (가정: 지표에는 문서 수만 필요하다).
- 옛 버전 보기(`/d/<번호>/v/<n>`)는 세지 않는다 (가정). 올린 사람 본인이 연 것도 센다.
- 기록이 실패해도 문서는 그대로 보여 주고 서버 로그에 `열람 기록 실패` 를 남긴다.
- 화면은 만들지 않았다. 지난 7일간 열람된 문서 수는 맥미니에서 아래로 본다.
  ```
  sqlite3 data/html-hub.db "SELECT COUNT(DISTINCT doc_id) FROM views WHERE at >= strftime('%s','now','-7 days')"
  ```
- 자동 테스트 19개 통과. 실서버 확인: 배포 뒤 문서를 한 번 열자 `views` 에 1행(문서 번호, 시각)이 생겼다.

## 관리자: 숨긴 문서 살리기 (2026-11-26)

정책서 D4-1(살리는 일은 관리자만)을 따랐다.

- 관리자(`role = admin`)에게만 목록 위에 "숨긴 문서" 링크가 보인다. `/admin/hidden` 은 최근에 숨긴 것부터 보여 주고, 행마다 "살리기"(`POST /d/<번호>/unhide`) 버튼이 있다.
- 살리면 목록·본문 검색에 다시 나오고 링크도 열린다. 버전·댓글은 그대로다. 숨겨져 있지 않은 문서를 살리려 하면 404 다.
- 일반 직원은 두 주소 모두 403 이다.
- 실서버 확인: 일반 직원으로 403 과 링크 숨김을 확인했다. 내 계정을 잠시 관리자로 바꿔 시험 문서를 숨기자 링크가 404 가 되고 숨긴 목록에 나왔다. 살리자 목록에 돌아오고 문서가 열렸으며, 한 번 더 살리면 404 였다. 시험 뒤 역할을 member 로 되돌렸다. 자동 테스트 21개 통과.
- 지난 시험에서 숨긴 문서 10건이 숨긴 목록에 남아 있다. 지우지 않았다.

## 관리자: 토큰 강제 폐기 (2026-11-26)

정책서 T5 가 위험으로 적어 둔 "토큰이 새면 그 직원 이름으로 올릴 수 있다"에 대한 대응이다.

- 관리자에게만 목록 위에 "토큰 관리" 링크가 보인다. `/admin/tokens` 는 폐기되지 않은 토큰을 최근 발급순으로 직원·발급 시각·마지막 사용 시각과 함께 보여 준다. 토큰 값은 서버에도 해시만 있으므로 보이지 않는다.
- "폐기"(`POST /admin/tokens/revoke`, 직원 이메일)를 누르면 그 직원의 활성 토큰이 폐기된다. 서버 로그에 `관리자 토큰 폐기: <관리자> 가 <직원> 의 토큰을 폐기` 를 남긴다. 직원은 `/tokens` 에서 다시 발급받을 수 있다.
- 일반 직원은 두 주소 모두 403 이다.
- 실서버 확인: 일반 직원으로 403 을 확인했다. 실제 MCP 토큰을 지키려고 가짜 이메일로 임시 토큰 행을 넣고, 내 계정을 잠시 관리자로 바꿔 그 행만 폐기했다. 목록에서 빠지고 로그가 남았다. 시험 뒤 역할을 member 로 되돌리고 임시 행을 지웠다. 자동 테스트 22개 통과.
- 유효기간과 올리기 횟수 제한(T5)은 여전히 없다.

## 검색 결과 발췌 (2026-11-26)

본문 검색(F1·F2)으로 걸린 문서가 왜 걸렸는지 보이게 했다.

- 검색어가 있으면 목록의 제목 아래에 현재 버전 본문에서 검색어가 처음 나오는 곳의 앞 40자부터 120자를 회색 글씨로 보여 준다 (가정). 대소문자는 무시한다.
- 본문에 없고 제목·올린 사람으로만 걸린 문서, 검색어가 없을 때는 발췌를 붙이지 않는다. 발췌를 못 읽어도 목록은 그대로 나온다.
- 검색어 강조 표시는 하지 않았다.
- 실서버 확인: 본문에만 있는 낱말로 찾자 발췌가 붙었고, 제목으로만 걸린 검색과 검색어 없는 목록에는 붙지 않았다. 자동 테스트 23개 통과.

## E2E 테스트 (2026-11-26)

인수 조건을 커밋된 자동 시험으로 옮겼다. `tests/e2e.rs`, 실행은 `cargo test --test e2e` (14개, 약 3초).

- 방식: 실제 바이너리를 시험마다 임시 DB·파일 폴더·빈 포트로 띄우고 HTTP 로 요청한다. 명단은 실제 `import-users` 명령으로 넣고, 관리자는 DB 에서 지정한다. 구글 로그인은 자동화할 수 없어서 서버와 같은 `SESSION_KEY` 로 세션 쿠키를 직접 암호화해 쓴다.
- 다루는 것: 공개 화면과 로그인 필요 화면, 명단에 없거나 비활성인 계정 차단, 위조 쿠키, 로그아웃, R1-1 입력 검사(제목·확장자·빈 파일·10MB·200자)와 링크, R1-2 열기(로그인 후 복귀 주소, 격리 헤더, 없는 문서, 열람 기록), R1-3 목록·검색·발췌, R1-4 프로젝트, 쪽 나누기, R1-5 삭제 권한과 숨김·관리자 살리기, R2 교체·이력·되돌리기, 토큰 올리기·재발급·폐기·비활성 계정, 관리자 토큰 폐기, R3 댓글 쓰기·지우기 규칙.
- 다루지 않는 것: 구글 로그인 콜백 자체(실서버에서 손으로 확인), 문서 속 JS 가 쿠키·localStorage·앱 요청을 못 쓰는지(헤더만 확인한다. 브라우저 동작은 2026-11-25 실서버에서 확인), 클립보드 복사 버튼.
- 시험이 버그를 잡는지 확인: 격리 헤더에 `allow-same-origin` 을 넣고 삭제 권한 검사를 없애자 E2E 3개가 실패했다.
- 처음에 병렬 시험이 가끔 실패했다. 임시 폴더 이름이 겹친 것(macOS 시계가 마이크로초 단위)과 빈 포트를 고른 뒤 다른 시험이 가로챈 것이 원인이었다. 폴더에 순번을 붙이고, 서버마다 다른 client_id 로 내 서버인지 확인하게 고친 뒤 15번 연속 통과했다.

## 올린 HTML 호환과 위조 요청 차단 (2026-11-26)

Claude 결과물에 흔한 HTML 4종(Chart.js·구글 폰트 리포트, Tailwind CDN, React + localStorage 앱, 표·접기·이미지 문서)을 실제 브라우저로 열어 봤다.

- 처음 결과: 차트·Tailwind·일반 문서는 정상. React 앱은 화면이 비었다(격리된 문서는 출처가 없어 localStorage 가 SecurityError). alert, 새 창 링크, 폼 제출, 다운로드도 막혔다.
- 고친 것 (사용자 결정): 격리 헤더를 `sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox allow-modals allow-forms allow-downloads` 로 넓혔다. `allow-same-origin`, `allow-top-navigation` 은 계속 주지 않는다. 문서를 내보낼 때 맨 앞(doctype 뒤)에 메모리용 localStorage/sessionStorage 대체 코드를 넣는다. 저장소가 막혔을 때만 동작하고, 값은 새로고침하면 사라진다. 저장된 파일은 바꾸지 않는다.
- 다시 확인: 네 문서 모두 표준 모드로 그려지고 React 카운터·alert·새 창이 동작했다. 문서 JS 의 쿠키 접근은 여전히 막힌다.
- 이때 발견한 구멍: `allow-forms` 를 주자 문서 속 폼이 자동 제출한 `POST /tokens` 가 사용자 이름으로 토큰을 발급했고 `POST /logout` 도 먹혔다. 폼 제출은 화면 이동이라 로그인 쿠키(SameSite=Lax)가 함께 간다.
- 막은 방법: 상태를 바꾸는 모든 요청(POST 등)은 `Origin` 헤더가 이 사이트(BASE_URL 의 출처)일 때만 받는다. 격리된 문서(`Origin: null`), 다른 사이트, Origin 없음은 403. 토큰으로 올리는 `/api/upload` 는 쿠키를 쓰지 않으므로 검사하지 않는다. 다른 사이트에서 보내는 위조 요청(CSRF)도 함께 막힌다.
- 확인: E2E 에 위조 요청 시험 추가(17개). 브라우저에서 같은 공격 문서가 403 에서 멈추고 토큰이 발급되지 않으며 로그인이 유지되는 것, 앱 화면의 폼(댓글, 삭제, 로그아웃)은 그대로 되는 것을 확인했다. 실서버에서 같은 출처 200, null·다른 사이트·Origin 없음 403.

## Claude 아티팩트 실서버 확인 (2026-11-27)

Claude 가 흔히 만드는 꼴 4가지(Chart.js 대시보드, Tailwind CDN, React 18 + Babel, Mermaid 문서)를 MCP 도구로 실서버에 올려 브라우저에서 열었다. 차트 그리기·탭 전환·localStorage(대체 저장소), Tailwind 스타일·CSV 내려받기, React 입력·추가·alert, Mermaid 도형·새 창 링크가 모두 동작했고 휴대폰 폭(375px)에서도 가로 넘침이 없었다.

- 이때 발견: 모든 문서에서 `SecurityError: Blocked a frame with origin "null"` 가 났다. 원인은 앱이나 문서가 아니라 Cloudflare 가 응답에 끼워 넣은 스크립트(Web Analytics beacon, JavaScript Detections)였다. 이 스크립트가 숨은 iframe 의 문서를 읽으려다 격리(sandbox) 때문에 막힌다.
- 고친 방법: 올린 문서 응답에만 `Cache-Control: no-transform` 을 붙여 Cloudflare 가 문서 내용을 바꾸지 않게 했다. 앱 화면은 그대로 둔다. 대신 이 응답은 Cloudflare 압축을 받지 않는다 (문서는 10MB 이하라 감수한다).

## 원격 MCP 와 Claude 연결 (2026-11-27)

로컬 MCP 스크립트는 PC 의 파일 경로만 받아 Claude Code 에서만 쓸 수 있었다. claude.ai 웹·데스크톱·모바일에서도 "survey 에 올려줘" 로 올릴 수 있게 원격 MCP 를 붙였다.

- 연결: claude.ai 설정 → 커넥터 → 사용자 지정 커넥터 추가에 `https://survey.eunseong.dev/mcp`. Claude Code 는 `claude mcp add --transport http survey https://survey.eunseong.dev/mcp` 뒤 `/mcp` 에서 로그인. 직원 토큰(hh_)을 `Authorization: Bearer` 로 줘도 된다.
- 로그인(OAuth 2.1): 메타데이터 → 동적 등록 → 승인 화면(구글 로그인 뒤 "허용") → 토큰 교환. PKCE(S256) 필수, 승인 코드는 10분·한 번만, 토큰은 90일이고 해시만 저장한다. 직원 토큰과 따로 두어 서로 폐기하지 않는다.
- 돌아갈 주소는 `https://claude.ai/api/mcp/auth_callback`, `https://claude.com/api/mcp/auth_callback`, 이 컴퓨터(localhost·127.0.0.1)만 받는다 (가정: 다른 MCP 클라이언트는 아직 필요 없다). 그래서 등록한 클라이언트를 저장하지 않는다. 승인 화면에는 클라이언트가 보낸 이름이 아니라 돌아갈 주소로 정한 이름(Claude (claude.ai) / 이 컴퓨터의 프로그램)을 보여 준다.
- 승인 화면은 다른 사이트가 겹쳐 띄우지 못하게 했고(`X-Frame-Options: DENY`), 허용 버튼은 이 사이트 화면에서 보낸 요청만 받는다. 허용하려면 "내가 Claude 에서 직접 연결을 눌렀다" 확인란을 따로 체크해야 한다 (보안 검토: 남이 시작한 claude.ai 연결 링크를 문서 속 새 창이나 메시지로 열게 해 엉겁결에 허용하게 만드는 공격을 줄인다). 배치 요청은 오류로 답하고, 로그인 뒤 돌아갈 승인 주소는 2048자까지 받는다. 연결은 내 토큰 화면의 "연결된 곳"에서 모두 끊을 수 있다. 명단에서 빠진 직원의 토큰은 살아 있어도 막는다.
- 도구 `upload_html`: title, content, format(html·md·svg·mermaid·jsx), project. 아티팩트 내용을 그대로 넘긴다. 로컬 스크립트도 같은 입력(content·format)을 받고 file_path 도 그대로 받는다.
- 확인: E2E 18개(원격 MCP·OAuth 전 과정 추가: 메타데이터, 401 안내, 이상한 돌아갈 주소 거절, 로그인 뒤 승인 화면 복귀, 거절·허용, 코드 재사용·PKCE 틀림 거절, 초기화·목록·올리기, 직원 토큰, 연결 끊기)·단위 34개 통과. 실서버에서 Claude Code 와 같은 방식(이 컴퓨터로 돌아오는 주소)으로 등록 → 휴대폰 폭 승인 화면에서 허용 → 토큰 → `.jsx` 올리기까지 됐다 (시험 토큰은 폐기). 로컬 스크립트의 content 올리기도 실서버에서 됐다.
- 확인 못 한 것: claude.ai 의 실제 커넥터 연결. Cloudflare 봇 차단이 claude.ai 서버의 요청을 막는지는 사용자가 커넥터를 추가해 봐야 안다.

## Codex 연결 (2026-11-27)

Codex CLI 도 같은 원격 MCP(`/mcp`)에 붙는다. 서버 쪽은 바꿀 게 없었다 — Codex 의 OAuth 는 이 컴퓨터(`http://127.0.0.1:<포트>/callback/...`)로 돌아오고 동적 등록을 쓰는데, 둘 다 이미 받는다. 승인 화면 이름과 내 토큰 화면 안내에 Codex 를 넣었다.

## 설문 응답 모으기 (2026-11-27)

올린 문서는 격리돼 있어 응답을 저장할 곳이 없었다. 문서를 내보낼 때 `window.htmlhub.submit({질문: 답})` 함수를 넣어, 설문 HTML 이 이 함수를 부르면 보고 있는 직원 이름으로 응답이 저장되게 했다. Claude 에게 "설문 만들어서 survey 에 올려줘" 하면 MCP 도구 설명을 보고 이 함수를 쓰는 HTML 을 만든다.

| 정한 것 | 내용 |
|---|---|
| 누가 결과를 보나 | 올린 사람과 관리자만 (가정). 문서의 "응답" 탭과 CSV |
| 몇 번 내나 | 한 사람이 한 문서에 하나. 다시 내면 덮어쓴다 (가정) |
| 익명인가 | 아니다. 이름·이메일·제출 시각이 남는다 (가정) |
| 형식 | 답은 JSON 객체, 64KB 까지. 열은 질문이 처음 나온 순서. 배열 답은 "A, B" 로 펼친다 |

- 작동: 문서를 열 때마다 그 문서·그 직원에게만 통하는 제출 열쇠(8시간, 메모리)를 저장소 대체 코드와 같은 script 에 넣는다. 문서 스크립트는 누가 보고 있는지 알 수 없다. 제출은 쿠키 대신 열쇠로 확인하므로 출처 검사에서 뺐고, 격리된 문서가 결과를 읽도록 `Access-Control-Allow-Origin: *` 를 준다(쿠키를 쓰지 않아 안전). 서버를 다시 켜면 열쇠가 사라져 "새로고침 뒤 다시 제출" 안내가 나간다.
- CSV 는 엑셀용 BOM 을 붙이고, `= + - @` 로 시작하는 칸은 앞에 `'` 를 붙여 수식으로 실행되지 않게 한다.
- 남은 위험: 문서를 만든 사람의 스크립트는 열쇠를 가지므로, 보는 사람 몰래 그 문서에 응답을 낼 수 있다. 영향은 그 문서의 응답에만 미친다. 옛 버전 보기(`/d/번호/v/n`)에는 제출 함수를 넣지 않는다. 응답 삭제·마감 기능은 없다.
- 확인: 단위 36개·E2E 19개(설문 추가: 제출 함수 삽입과 원본 보존, Origin null 제출·CORS, 덮어쓰기, 틀린 열쇠·다른 문서·객체 아님·64KB 초과 거절, 결과 권한, 응답 탭, 질문 순서, CSV BOM·수식 무력화) 통과. 실서버 휴대폰 폭에서 Tailwind 설문을 채워 제출 → "제출했습니다" → 응답 탭·CSV 에 그대로 나왔다.

## 외부 검토(Fable 5.2) 반영 1: 보안 (2026-11-27)

다른 모델(Fable 5.2)에게 코드·문서를 처음 보는 눈으로 검토받았고, 사용자가 전부 진행하기로 했다. 먼저 보안부터.

- **설문 CSV 캐시(P0)**: 응답에 캐시 규칙이 없어 Cloudflare 가 `.csv` 주소를 캐시할 수 있었다 (로그인 없이 이름·응답 노출). 앱의 모든 응답에 따로 정하지 않았으면 `Cache-Control: private, no-store` 를 붙였다. 그래도 `.csv` 로 끝나는 주소는 Cloudflare 가 브라우저 캐시 기한을 4시간으로 덮어써서, CSV 주소를 `/d/<번호>/responses/csv` 로 바꿨다. 실서버에서 `DYNAMIC`·`private, no-store` 확인.
- **문서 틀(정책서 M4 변경)**: `/d/<번호>` 는 위 줄(제목·댓글·이력·응답·새 창) + 격리된 iframe(`/d/<번호>/raw`). 열람 수는 틀을 연 번만 센다.
- **설문 제출을 앱이 확인**: 문서 스크립트가 보는 사람 몰래 `htmlhub.submit` 을 불러 이름을 모을 수 있었다. 이제 문서는 틀에 메시지만 보내고, 틀이 "○○ 이름으로 제출할까요?" 와 보낼 답을 보여 준 뒤 허락하면 로그인 쿠키로 낸다. 제출 열쇠·출처 검사 예외·CORS 가 모두 없어졌고, 배포(재시작)해도 작성 중인 설문이 날아가지 않는다. `/raw` 를 따로 열면 제출할 수 없다고 알린다.
- **퇴사자·역할**: `html-hub import-users --deactivate-missing <파일>` 은 파일에 없는 활성 계정을 끄고 목록을 찍는다 (손으로 넣은 개인 계정도 꺼지므로 주의). `html-hub user <이메일> <admin|member|off> [이름]` 로 역할을 바꾸거나 끄거나 새로 넣는다. 직원 토큰은 1년 뒤 만료(정책서 T5 변경).
- 확인: 단위 38개·E2E 19개. 실서버 휴대폰 폭에서 설문 제출 → 확인 창(답 목록·이름) → 제출/취소, React·복사·전체 화면이 틀 안에서 동작.
