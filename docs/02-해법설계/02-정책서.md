>
> 정책서는 화면에 안 그려지는 규칙을 적는다. 각 규칙에 **정함**(사용자가 결정)과 **가정**(내가 임시로 둠, 확인 필요)을 표시했다.

## 접근

| # | 규칙 | 구분 |
|---|---|---|
| A1 | 회사 구글 계정(`@greenery.im`)으로 로그인한 사람만 모든 화면과 문서를 볼 수 있다 | 정함 |
| A2 | 사내 전용이다. 회사 밖 사람에게 보내는 외부 공유 링크는 만들지 않는다 | 정함 |
| A3 | 로그인한 직원은 모든 문서를 볼 수 있다. 프로젝트·팀은 분류용이고 열람 범위를 나누지 않는다 | 정함 |
| A4 | 로그인 계정이 `@greenery.im` 이 아니면 접근 불가 안내만 보인다 | 정함 (A1의 결과) |

## 올라온 HTML 의 안전

올라온 HTML 은 안에 든 JS 가 그대로 실행된다. 이 규칙은 기능이 아니라 안전 때문에 필요하다.

| # | 규칙 | 구분 |
|---|---|---|
| S1 | 문서를 보여 주는 주소와 로그인·관리 화면의 주소는 서로 다른 도메인으로 둔다. 같은 도메인이면 문서 안의 JS 가 로그인 세션을 쓸 수 있다 | 가정 (설계 단계에서 구체화) |
| S2 | 문서를 보여 줄 때 로그인 확인은 거친다. 문서 주소가 추측 가능한 공개 링크가 되면 A1 이 깨진다 | 가정 (설계 단계에서 구체화) |
| S3 | 올리는 사람이 고객 정보·비밀값을 HTML 에 넣지 않는 책임은 올리는 사람에게 있다. 서비스가 내용을 검사하지는 않는다 | 가정 |

## 전 직원 열람의 부담

A3 때문에 올리는 사람이 불안할 수 있다. 예를 들어 고객 정보가 섞인 분석 결과를 올리면 전 직원이 열 수 있다.

- MVP 에서는 올리기 화면에 "전 직원이 볼 수 있습니다" 문구를 보인다 (가정)
- 비공개 문서나 팀 제한 공개는 MVP 에서 하지 않는다. 필요하다는 신호가 오면 다시 정한다 (가정)

## 아직 정하지 않은 것

- D2 관리자를 누구로 할지
- D4 삭제 복구 기간
- 본문 검색 여부 (지금은 제목·올린 사람만)
- 같은 문서를 새 버전으로 바꿀 때의 규칙 (버전 관리 우선순위를 정한 뒤)
