# 정책서

> 단계: 해법 설계 / 상태: 초안 / 작성일: 2026-11-11
>
> 정책서는 화면에 안 그려지는 규칙을 적는다. 각 규칙에 **정함**(사용자가 결정)과 **가정**(내가 임시로 둠, 확인 필요)을 표시했다.

## 접근

| # | 규칙 | 구분 |
|---|---|---|
| A1 | 회사 구글 계정(`@greenery.im`)으로 로그인한 사람만 모든 화면과 문서를 볼 수 있다 | 정함 |
| A2 | 사내 전용이다. 회사 밖 사람에게 보내는 외부 공유 링크는 만들지 않는다 | 정함 |
| A3 | 로그인한 직원은 모든 문서를 볼 수 있다. 프로젝트·팀은 분류용이고 열람 범위를 나누지 않는다 | 정함 |
| A4 | 로그인 계정이 `@greenery.im` 이 아니거나, 아래 C1 에 따라 미리 등록된 계정이 아니면 접근 불가 안내만 보인다 | 정함 |

## 계정

| # | 규칙 | 구분 |
|---|---|---|
| C1 | 모든 직원의 계정을 소속까지 포함해 미리 등록해 둔다. 회사 구글 계정으로 로그인해도 등록되지 않은 계정은 들어올 수 없다 | 정함 |
| C2 | 계정 정보는 이메일, 이름, 소속, 역할(일반 / 관리자)이다 | 가정 |
| C3 | 소속은 분류와 "올린 사람" 표시에 쓴다. 소속으로 열람 범위를 나누지는 않는다 (A3 유지) | 가정 |
| C4 | 퇴사자 계정은 비활성으로 바꾼다. 퇴사자가 올린 문서는 남는다 | 가정 |
| C5 | 계정 원본은 구글 워크스페이스의 "사용자 다운로드" JSON 이다. 이 파일을 불러와(`html-hub import-users`) 등록하고, 소속은 사용자가 직접 입력한다. 입사·퇴사는 파일을 다시 불러와 반영한다. 정지(Suspended) 상태는 비활성으로 바뀌지만, 파일에 없는 사람은 비활성으로 바꾸지 않는다. Directory API 자동 동기화는 필요해질 때 정한다 | 정함 (MVP) |
| C6 | 직원 명단(이메일, 이름, 소속)은 이 레포에 커밋하지 않는다. 레포가 public 이기 때문이다. 명단은 배포 환경의 DB 로만 넣는다 | 정함 (안전 원칙) |

## 수정·삭제

| # | 규칙 | 구분 |
|---|---|---|
| D1 | 문서는 올린 사람과 관리자만 수정·삭제할 수 있다 | 정함 |
| D2 | 관리자는 IT 팀이다 | 정함 |
| D2-1 | IT 팀원은 계정의 역할 값(C2)이 "관리자"인 사람으로 알아본다 | 가정 |
| D3 | 삭제한 문서의 링크는 "없는 문서" 안내가 보인다 | 가정 |
| D4 | 삭제한 문서는 화면에서만 숨기고 저장소에는 그대로 가지고 있는다. 보관 기간은 두지 않는다 | 정함 |
| D4-1 | 숨긴 문서를 다시 살리는 일은 관리자(IT 팀)만 한다 | 가정 |
| D4-2 | 파일은 S3 에 두므로 보관 기간 때문에 저장 공간을 걱정하지 않는다. 다만 S3 비용은 쌓이므로 운영 단계에서 한 번 본다 | 정함 (사용자 판단) |
| D4-3 | 본문 검색 색인은 S3 가 아니라 검색 쪽에 따로 쌓인다. 숨긴 문서와 이전 버전을 색인에서 어떻게 다룰지는 설계 단계에서 정한다 | 가정 |

## 찾기

| # | 규칙 | 구분 |
|---|---|---|
| F1 | 검색 대상은 제목, 올린 사람, 문서 본문이다 | 정함 |
| F2 | 본문 검색은 HTML 태그와 스크립트를 뺀 보이는 글자를 대상으로 한다 | 가정 |
| F3 | 숨긴(삭제한) 문서는 검색 결과에 나오지 않는다 | 가정 |
| F4 | 검색 결과에는 문서 본문 일부가 함께 보일 수 있다. 열람 범위는 문서와 같다(A3) | 가정 |

본문을 검색하면 올리는 사람이 의식하지 못한 내용(표 안의 이름, 숫자 등)도 검색에 걸린다. A3 의 "전 직원 열람의 부담"이 더 커지는 지점이다.

## 올라온 HTML 의 안전

올라온 HTML 은 안에 든 JS 가 그대로 실행된다. 이 규칙은 기능이 아니라 안전 때문에 필요하다.

| # | 규칙 | 구분 |
|---|---|---|
| S1 | 문서를 보여 주는 주소와 로그인·관리 화면의 주소는 서로 다른 도메인으로 둔다. 같은 도메인이면 문서 안의 JS 가 로그인 세션을 쓸 수 있다 | 가정 (설계 단계에서 구체화) |
| S2 | 문서를 보여 줄 때 로그인 확인은 거친다. 문서 주소가 추측 가능한 공개 링크가 되면 A1 이 깨진다 | 가정 (설계 단계에서 구체화) |
| S3 | 올리는 사람이 고객 정보·비밀값을 HTML 에 넣지 않는 책임은 올리는 사람에게 있다. 서비스가 내용을 검사하지는 않는다 | 가정 |

## 전 직원 열람의 부담

A3 때문에 올리는 사람이 불안할 수 있다. 예를 들어 고객 정보가 섞인 분석 결과를 올리면 전 직원이 열 수 있다.

- MVP 에서는 올리기 화면에 "전 직원이 볼 수 있습니다" 문구를 보인다 (가정)
- 비공개 문서나 팀 제한 공개는 MVP 에서 하지 않는다. 필요하다는 신호가 오면 다시 정한다 (가정)
