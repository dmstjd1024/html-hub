## 주소(도메인)

**앱 주소는 `survey.eunseong.dev` 로 한다 (정함, 임시).** `eunseong.dev` 는 이미 Cloudflare 에 있고 `survey` 기록은 비어 있다 (2026-11-24 확인). 맥미니에는 `macmini-tunnel` 이 이미 있다. 다만 개인 도메인이라 회사 서비스가 한 사람의 도메인에 걸린다. 회사 주소로 옮길 때는 리디렉션 URI 와 `BASE_URL` 만 바꾸면 된다.

아래는 정하기 전에 비교한 방법이다.

Cloudflare Tunnel 로 주소를 붙이려면 그 도메인이 Cloudflare 계정에 있어야 한다. 그런데 `greenery.im` 의 이름 서버(DNS)는 AWS Route 53 이다 (`dig NS greenery.im` 으로 확인, 2026-11-24).

| 방법 | 장점 | 단점 |
|---|---|---|
| A. 새 도메인을 사서 Cloudflare 에 둔다 | 메일 등 기존 `greenery.im` 설정을 건드리지 않는다. 문서용 별도 도메인(아래)도 같이 해결된다 | 도메인 비용. 직원이 보는 주소가 `greenery.im` 이 아니다 |
| B. `greenery.im` 전체를 Cloudflare 로 옮긴다 | `hub.greenery.im` 처럼 회사 주소를 쓴다 | 메일(MX) 등 모든 기록을 옮겨야 한다. 잘못하면 회사 메일이 끊긴다 |
| C. `greenery.im` 은 Route 53 에 두고 일부만 연결한다 | 회사 주소를 쓰고 이전도 없다 | Cloudflare 의 부분(CNAME) 설정이 필요하고, 이게 Cloudflare 무료 요금제에서 되는지 확인하지 못했다 |

근거: [Cloudflare Tunnel DNS 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/dns/), [라우팅 개념](https://developers.cloudflare.com/tunnel/concepts/routing/). 부분 설정에서 연결 대상 이름이 문서마다 달라 실제 대시보드에서 확인해야 한다.

## 문서를 보여 주는 주소 — 가정 (S1 구체화)

업로드된 HTML 안의 JS 는 그대로 실행된다. 문서 주소가 앱 주소의 하위 도메인(`docs.example.com` ↔ `hub.example.com`)이면 같은 사이트로 취급된다. 그러면 문서 속 JS 가 앱에 요청을 보낼 때 `SameSite=Lax` 쿠키가 따라가서, 로그아웃이나 올리기 같은 POST 를 문서가 대신 일으킬 수 있다.

그래서 **문서 주소는 앱과 다른 등록 도메인**으로 둔다 (예: 앱 `hub.aaa.com`, 문서 `docs.bbb.com`). 이 판단은 내 것이고 실제 공격을 재현해 본 것은 아니다. 앱이 `eunseong.dev` 아래에 있으므로 문서 주소는 `eunseong.dev` 의 하위 도메인이 아닌 **다른 도메인**이어야 한다. 이 도메인은 아직 정하지 않았다 (미정).

문서 주소에서도 로그인 확인은 거쳐야 한다(S2). 앱이 짧게 쓰이는 서명 링크를 발급하는 방식을 설계 때 정한다.

## 저장과 검색

| # | 내용 | 구분 |
|---|---|---|
| I4 | DB 는 SQLite 한 파일이다 (이미 명단에 쓰고 있다). 본문 검색은 SQLite 의 전문 검색(FTS5)으로 시작한다. 구현 때 쓰는 빌드에 FTS5 가 켜져 있는지 확인한다 | 가정 |
| I5 | 문서 파일을 맥미니 디스크에 둘지, S3 나 Cloudflare R2 에 둘지는 정하지 않았다. 정책서 D4-2 는 S3 를 전제로 썼다 | 미정 |
| I6 | 맥미니가 꺼지거나 고장 나면 서비스가 멈춘다. DB 와 문서 파일은 정기적으로 다른 곳에 백업한다. 재부팅하면 서버와 터널이 저절로 켜지도록 `launchd` 에 등록한다 | 가정 |

I5 의 기준: 디스크는 가장 단순하고 비용이 없지만 맥미니 한 대에 모든 것이 달려 있다. 바깥 저장소는 비용이 들지만 맥미니를 잃어도 문서가 남는다. 문서 이력과 삭제 보관(D4)을 영구히 두기로 했으므로 **문서가 맥미니 안에만 있는 것을 받아들일 수 있는지**가 핵심이다.
