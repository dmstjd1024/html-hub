# 역기획: 로컬 HTML 을 팀에 공유하는 지금의 방법들

> 단계: 문제 정의 / 상태: 초안 / 작성일: 2026-11-11
>
> 이 문서의 결론은 적용안이 아니라 **가설**이다. 가설은 만들면서 검증한다.

## 풀려는 문제

Claude 같은 도구가 만든 `.html` 결과물이 만든 사람의 로컬 디스크에만 있다. 다른 팀원이 브라우저에서 바로 여는 링크가 없다.

## 지금 쓸 수 있는 대안 4개

"링크 하나로 열리나"와 "회사 계정으로 제한되나"를 가장 먼저 본다. 이 둘이 안 되면 문제가 그대로 남기 때문이다.

| 대안 | 링크 하나로 열리나 | 로그인 제한 | 확인 상태 |
|---|---|---|---|
| 슬랙에 파일 첨부 | 아니다. 내려받아서 열어야 한다 | 채널 멤버 | 확인함 (2026-11-11 시험 업로드를 본인 DM 에서 직접 봤다. 내려받기만 가능했다. 호스팅 업체 글 중 2026-06 부터 렌더가 시작됐다는 주장은 우리 워크스페이스에서는 확인되지 않았다) |
| claude.ai Artifact | 열린다. 호스팅된 페이지이고 기본은 비공개다 | 계정 기반 | 부분 확인 (지원 문서상 Team·Enterprise 플랜은 조직 전체나 지정한 사람에게 공유할 수 있다. 실제 사용 경험으로는 공유해도 다른 사람은 읽기만 가능했고 올리는 쪽은 개인이었다. 우리 조직의 플랜은 미확인) |
| 사내 위키(Outline) | 아니다. 첨부는 되지만 열면 내려받는다 | 위키 로그인 | 확인함 (2026-11-11 시험 업로드. 첨부 파일 응답 헤더가 `Content-Disposition: attachment` 라서 브라우저가 렌더하지 않고 내려받는다. 헤더로 확인했고 브라우저 화면은 보지 않았다) |
| S3 정적 호스팅 | 열린다 | 기본은 공개다. 제한하려면 CloudFront 에 인증을 따로 붙여야 한다 | 일반 지식 (이 팀 계정에서 실측하지 않음) |

네 대안 모두 "회사 계정으로 로그인한 사람만, 링크 하나로 열리고, 목록과 검색이 된다"를 한꺼번에 만족하지는 않는 것으로 보인다. 위 표의 미확인 칸이 채워지면 이 문장은 바뀔 수 있다.

## 가설

| # | 가설 | 틀렸다면 | 검증 방법 |
|---|---|---|---|
| H1 | 올리는 사람이 파일을 첨부하는 것보다 링크 한 줄을 붙이는 쪽이 낫다고 느낀다 | 슬랙 첨부로 충분하다는 뜻이고, 서비스를 만들 이유가 약해진다 | 슬랙 첨부는 내려받기만 되는 것을 확인했다(2026-11-11). 남은 것은 올리는 사람 쪽 불편을 팀원에게 묻는 것이다 |
| H2 | 보는 사람은 새 로그인 없이 회사 구글 계정으로 열기를 기대한다 | 별도 계정이나 다른 인증을 원한다는 뜻이다 | 보는 사람 2~3명에게 물어본다 |
| H4 | Artifact 는 올리는 사람이 개인이고 다른 사람은 읽기만 해서, 여럿이 올리고 한곳에서 모아 보는 공간이 따로 필요하다 | Artifact 로 충분하다는 뜻이고, 이 서비스의 차별점이 사라진다 | 우리 조직의 Artifact 공유 범위를 확인하고, 팀원 2~3명이 Artifact 를 어떻게 쓰고 있는지 묻는다 |
| H3 | 링크 공유만으로는 부족하고, 나중에 다시 찾는 목록·검색이 함께 있어야 쓴다 | 링크만 있어도 충분하다는 뜻이고, MVP 에서 목록·검색을 뺄 수 있다 | 슬랙에서 예전 HTML 을 다시 찾아본 경험이 있는지 팀에 묻는다 |

## 한계

- 대안 4개의 동작은 아직 우리 환경에서 직접 확인하지 않았다. 표의 확인 상태 칸이 어디까지 확인했는지를 보여준다.
- 다른 대안(노션, 구글 드라이브 미리보기 등)은 비교하지 않았다.
- 이 문서는 한 사람의 관점에서 쓴 것이다. 보는 사람의 의견은 아직 반영되지 않았다.
