# 인수인계 (2026-11-27 갱신)

> 이 문서 하나로 html-hub 를 운영·배포·복구하고 이어서 개발할 수 있게 쓴다. 바뀐 이력과 근거는 `docs/03-명세/01-PRD-R1.md`(날짜별 기록), 정책은 `docs/02-해법설계/02-정책서.md`, 인프라 결정은 `04-인프라.md` 에 있다.

## 한 줄 요약

사내 직원이 HTML(및 Markdown·SVG·Mermaid·React `.jsx`) 문서를 올려 링크로 나누고, 버전·댓글·설문 응답을 남기는 서비스다. `https://survey.eunseong.dev` 에서 돌고 있고, Claude(claude.ai·데스크톱·Claude Code)와 Codex 가 MCP 로 바로 올린다.

## 지켜야 할 제약

- 비밀값(구글 클라이언트 시크릿, `SESSION_KEY`, 토큰)은 출력하거나 커밋하지 않는다. `.env` 는 600.
- 레포는 공개다. 직원 명단·회사 정보·비밀값을 커밋하지 않는다.
- `pople-project/html-hub` fork 는 개인 레포가 끝날 때까지 sync 하지 않는다. 끝났는지는 사용자가 정한다.
- 직원 명단은 사용자 승인 없이 복사하거나 넣지 않는다.
- 바깥으로 나가는 일(메시지 전송, 터널 재시작, 외부 서비스 설정)은 사용자에게 먼저 확인한다. `cloudflared` 를 재시작하면 같은 터널의 다른 호스트 9개가 몇 초 끊긴다.
- 커밋 작성자는 naver 이메일이다. 회사 메일을 로컬 설정에 넣지 않는다.

## 구조 한눈에

| 주소 | 하는 일 |
|---|---|
| `/` | 로그인 전: 소개 + "Google 계정으로 로그인". 로그인 뒤: 대시보드(목록·검색·프로젝트·많이 본 문서·최근 댓글) |
| `/d/<번호>` | 앱 틀: 위 줄(제목·댓글·이력·응답·새 창) + 격리된 iframe. 공유 링크는 이 주소다 |
| `/d/<번호>/raw` | 문서 원본. `CSP: sandbox …`(same-origin 없음), 메모리 저장소 대체 코드와 설문 제출 함수를 붙인다 |
| `/d/<번호>/history`·`/comments`·`/replace`·`/responses`(`/csv`) | 이력·되돌리기, 댓글, 새 버전·제목 고치기, 설문 응답(올린 사람·관리자) |
| `/upload`, `/tokens`, `/admin/hidden`, `/admin/tokens` | 올리기, 내 토큰·Claude 연결, 숨긴 문서(살리기·완전 삭제), 토큰·연결 관리 |
| `/mcp`, `/oauth/*`, `/.well-known/oauth-*` | 원격 MCP 와 그 로그인(OAuth 2.1). 공개 주소지만 토큰 없이는 401 |
| `/api/upload` | 직원 토큰으로 올리기 (curl 용) |
| `/healthz` | DB 표를 읽고 문서 폴더를 확인한다. 바깥 감시·배포 스크립트가 본다 |

- 로그인: 구글 OIDC, 명단(`users`)에 있는 활성 계정만. 회사 도메인 검사는 하지 않는다 — 명단이 기준이다. 세션 8시간.
- 상태를 바꾸는 요청은 `Origin` 이 이 사이트일 때만 받는다 (토큰으로 받는 `/api/upload`·`/mcp`·`/oauth/token`·`/oauth/register` 제외).
- 모든 앱 응답은 기본 `Cache-Control: private, no-store`, `X-Frame-Options: SAMEORIGIN`.
- 설문: 문서 스크립트가 `window.htmlhub.submit({질문: 답})` 을 부르면 앱 틀이 "○○ 이름으로 제출할까요?" 를 묻고 허락하면 쿠키로 낸다.
- 한 사람이 하루(24시간) 200건까지 올린다 (웹·토큰·MCP).

## 현재 상태 (2026-11-27)

- 코드: `main` 이 origin 과 같다. 테스트는 `cargo test` 로 단위 38개 + E2E 23개(`tests/e2e.rs`).

- 구글 OAuth: 프로젝트 `html-hub-515801`(silvercastle1024@gmail.com, 조직 없음), 외부 + 프로덕션 게시, 스코프 `openid email`.

## 맥미니 밖 (원격 백업·바깥 감시)

| 무엇 | 내용 |
|---|---|
| R2 버킷 `html-hub-backups` | 백업 작업이 매일 최신 DB 스냅샷 + 파일을 묶어 `openssl enc -aes-256-cbc -pbkdf2 -iter 200000` 으로 암호화해 올린다. 30개 보관. 키는 맥미니 `~/.config/html-hub/backup.key` 와 **1Password `env` 금고 `env-html-hub` 항목의 `BACKUP_KEY`** |
| Worker `html-hub-ops` (`ops/worker/`) | `PUT/GET /backup/<이름>`(`latest` 가능, 업로드 비밀값), `POST /check`(감시 비밀값): `/healthz` 와 원격 백업 나이를 보고 바뀔 때만 텔레그램. 배포는 `ops/worker` 에서 `npx wrangler deploy` (`~/eunseong-project/.env` 의 `CLOUDFLARE_API_TOKEN`). 비밀값 `UPLOAD_SECRET`·`CHECK_SECRET`·`TG_TOKEN`·`TG_CHAT` |
| GitHub Actions `monitor` (`.github/workflows/monitor.yml`) | 5분마다 Worker `/check` 를 부른다 (Workers 무료 크론 5개를 다른 Worker 가 쓰고 있어서). 레포 Secrets `MONITOR_SECRET` = Worker `CHECK_SECRET`. 레포에 60일 동안 활동이 없으면 GitHub 가 멈추니 Actions 화면에서 다시 켠다 |

`.env` 의 백업 변수: `BACKUP_UPLOAD_URL`(Worker 주소), `BACKUP_UPLOAD_SECRET`, `BACKUP_KEY_FILE`.

`.env` 변수: `BASE_URL`, `BIND_ADDR`(127.0.0.1:3000), `DATABASE_PATH`(절대 경로), `SESSION_KEY`(64자 이상), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. 선택: `FILES_DIR`, 백업 쪽 `BACKUP_REMOTE`(rsync 대상), `ALERT_WEBHOOK`(Slack).

## 복구 절차

1. 서버를 멈춘다: `launchctl bootout gui/$(id -u)/dev.eunseong.html-hub`
2. 지금 DB 를 따로 둔다: `cp data/html-hub.db data/html-hub.db-wal data/html-hub.db-shm <안전한 곳>/` (없는 파일은 넘어가도 된다)
3. 스냅샷을 고른다: 매일 것은 `~/backups/html-hub/db/html-hub-YYYYMMDD-HHMMSS.db`, 배포 전 것은 `db/manual/before-deploy-*.db`
4. 바꿔 넣는다: `cp <스냅샷> data/html-hub.db && rm -f data/html-hub.db-wal data/html-hub.db-shm`
5. 파일을 채운다: `rsync -a ~/backups/html-hub/files/ data/files/`
6. 다시 켠다: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.eunseong.html-hub.plist` → `curl -s 127.0.0.1:3000/healthz` 가 `ok`
7. 주의: 완전 삭제 전에 찍은 스냅샷이면 지운 문서의 기록(제목·본문 색인 글자)이 되살아난다. 파일은 없으니 `/admin/hidden` 에서 다시 완전 삭제한다.

2026-11-27 에 최신 스냅샷과 파일 백업을 임시 폴더로 옮겨 띄워 `/healthz` ok, 파일 누락 0건을 확인했다.

**맥미니를 잃었을 때 (R2 에서)**: 새 기계에서 레포를 받고, 1Password `env/env-html-hub` 의 `BACKUP_KEY` 를 파일로 만든 뒤 Cloudflare 대시보드(R2 → `html-hub-backups`)에서 최신 백업을 받는다(맥미니의 `.env` 가 남아 있으면 `curl -H "Authorization: Bearer $BACKUP_UPLOAD_SECRET" -o b.enc $BACKUP_UPLOAD_URL/backup/latest`). `openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -pass file:<키> -in b.enc | tar -xz` 하면 `db/html-hub-*.db` 와 `files/` 가 나온다. 이것을 `data/html-hub.db`, `data/files/` 로 두고 위 6번부터. 2026-11-27 에 R2 → 1Password 키로 풀기 → integrity ok, 문서 28건·파일 32개를 확인했다.

## Claude·Codex 연결 (직원 안내는 `/tokens` 화면에도 있다)

- claude.ai·Claude 데스크톱·모바일: 설정 → 커넥터 → 사용자 지정 커넥터 추가 → `https://survey.eunseong.dev/mcp` → 구글 로그인 → 확인란 체크 → 허용.
- Claude Code: `claude mcp add --transport http survey https://survey.eunseong.dev/mcp` 뒤 `/mcp` 에서 로그인.
- Codex: `codex mcp add survey --url https://survey.eunseong.dev/mcp` (바로 브라우저 로그인), 다시 로그인은 `codex mcp login survey`.
- 토큰 방식(로컬): `claude mcp add html-hub -e HTML_HUB_URL=https://survey.eunseong.dev -e HTML_HUB_TOKEN=<hh_ 토큰> -- python3 <레포>/scripts/mcp_upload.py`. 스크립트는 원격 `/mcp` 중계기이고 `file_path` 만 더한다.
- 도구: `upload_html`(새 문서), `update_html`(기존 문서 새 버전·제목, 올린 사람·관리자), `list_documents`(찾기).
- 돌아갈 주소는 claude.ai·claude.com 콜백과 이 컴퓨터(localhost)만 받는다. 다른 MCP 클라이언트를 받으려면 `src/mcp.rs` 의 `client_of` 를 고친다.

## 앞으로 할 일 (사용자 입력이 필요하다)

1. **재부팅 뒤 자동 복구.** FileVault 가 켜져 있고 자동 로그인이 없어, 정전 뒤 재부팅되면 누가 로그인할 때까지 서버·터널·백업·감시가 모두 멈춘다. 계획된 재부팅은 `sudo fdesetup authrestart` 로 한다.
2. **전체 직원 명단.** 워크스페이스 내보내기 JSON 을 받으면(사용자 승인 뒤) `import-users` 로 넣는다.
3. **R2 저장소(문서 파일 자체).** 버킷·키가 생기면 `src/docs.rs` 의 파일 다루는 곳(`put_file`·`read_file`, `replace` 의 이름 바꾸기, `purge`, `ping`)과 `scripts/backup.sh` 를 바꾼다.
4. **회사 주소로 옮길 때.** 구글 리디렉션 URI, `BASE_URL`, 터널 호스트, MCP 도구 설명의 주소(`src/mcp.rs`), Worker 의 `HEALTH_URL`, claude.ai·Codex·Claude Code 연결을 모두 다시 한다.

## 알려진 한계

- 문서는 격리돼 있어 IndexedDB·쿠키·새로고침 뒤에도 남는 localStorage·OpenStreetMap 타일이 안 된다 (풀려면 문서용 별도 도메인). claude.ai 전용 기능(`window.storage`, `window.claude.complete`, `window.fs`)도 없다. `.jsx` 는 shadcn/ui 를 쓰면 그리지 못한다.
- 본문 검색은 `instr` 로 전부 훑는다 (문서가 수천 건이 되면 FTS5 로).
- OAuth 승인 코드는 메모리에만 있다 — 연결 도중 서버를 재시작하면 다시 연결한다.
- 하루 한도는 되돌리기도 한 건으로 세지만, 되돌리기 자체는 막지 않는다 (새 파일이 생기지 않는다).
- 댓글 수정·알림, 설문 마감·삭제·익명 설문은 없다.
- 로그는 백업 작업(매일 03:30)이 5MB 를 넘는 파일을 `.1` 로 복사하고 비운다 (html-hub·cloudflared, 직전 한 벌만).
- 의존성: `cargo audit`(brew `cargo-audit`)을 손으로 돌린다. 2026-11-27 에 `cookie`·`url` 을 패치했다. 남은 `rsa` 0.9 의 RUSTSEC-2023-0071(개인키 연산 시간 차 공격)은 `openidconnect` 가 끌어오는데, 이 앱은 구글 서명을 공개키로 확인만 해서 해당하지 않는다. `chrono` 는 유지보수 중단 경고.

## 잔여물

- 레포의 추적되지 않는 `.omc/` 폴더(커밋하지 않는다).
- 실서버 "테스트" 프로젝트의 시험 문서들 (사용자가 남겨 두기로 함).

## 작업 방식 메모

- 문서(`docs/`)는 블로그 「웹 서비스 개발 단계」 순서를 따른다. 결정은 **정함**(사용자) / **가정**(임시) / **미정** 으로 구분한다.
- 사용자에게 답이 필요하면 `AskUserQuestion` 으로 묻는다.
- 브라우저 시험은 `ego-browser` 로 한다. 문서 iframe 은 다른 프로세스라 `evaluate` 로 못 읽으니 `page.snapshot()` 으로 본다. 클릭은 iframe 안까지 찾아간다.
